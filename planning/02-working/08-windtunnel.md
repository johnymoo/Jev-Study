# 08 — WindTunnel（WebMCP 表征基准：感知/判断解耦）

- 研究日期：2026-09-20
- 仓库：https://github.com/nekuda-ai/WindTunnel，commit `5ca8644`（2026-09-18）
- 许可证：Apache-2.0；基于 W3C WebMCP 规范（webmachinelearning/webmcp）

## 概述

基准仓库，比较浏览器 agent 操作网站的三/四种接口：截图（computer use）、页面结构（DOM/a11y 树）、代码执行（Playwright）、**WebMCP**（网站直接暴露 `add_to_cart(id)`、`book_slot(time)` 等工具调用）。规模：21 配置 × 49 任务 × 8 站点 × 3 次 = 3,087 attempt 行、1,029 多数裁决，600s/次上限（canonical board v1.2，2026-09-18）。

## 架构分析

WebMCP 是"网站自己提供语义化动作"的表征方案——agent 不再解析像素或 DOM，而是调用站点声明的能力。各 method（`arms/`）+ 模型组合成 21 个配置；多数裁决 + 负控站点（不该行动时只能回答）+ outcome probe（只读探查真实状态判定成败）+ perturbation（改名按钮/弹窗等对抗扰动，单独报告）。

## 基准数据（文章声称 vs 仓库实际证据）

| 文章声称 | 仓库证据 | 判定 |
|---|---|---|
| 同一模型原始 DOM 表 25/49（中位 5.4s），换 WebMCP 后 49/49（中位 3.2s） | README："New: Jev + Mercury 2.5 solves **49/49 tasks with WebMCP** and **25/49 with ultrafast DOM controls**"；WebMCP 对该组合 1.7× 更快 | ⚠️ 完成率数字 ✅ 可证实；5.4s/3.2s 中位耗时未在 README 出现（或在 results/ 明细中），1.7× 与之方向一致 |
| 表征改造拉开 44 个百分点，远超模型间 3.8 个百分点 | 49-25=24 个百分点（25/49≈51%→100%），文章的"44 个百分点"系错误换算 | ❌ **数字有误**（实际 +24pp），但"表征差距 >> 模型差距"的定性结论成立 |
| 表征改造是头号功臣属工程推断、无消融实验 | 仓库未提供"同表征下换判断模型"的隔离消融；且 9 个 WebMCP 配置 + GPT-6 Astra 代码执行均满分 49/49，"任务解出率"上 WebMCP 与最强截图方案打平，**区分度来自成本与时间**（3–47× 便宜、2.5–7.5× 快） | ✅ 消融缺口属实；文章的"44pp 成功率跃升"表述夸大了 |

另注意：GPT-6 Astra 代码执行总成本 $35.53 vs 原生 WebMCP $3.33（10.7×），中位时间 16.4s vs 6.3s。

## 评估结论

WindTunnel 证实"感知/判断解耦 + 表征改造"能带来数量级的成本/时间收益，但文章两处转述失真（44pp 应为约 24pp；成功率上 WebMCP 并未独占满分）。更准确的版本是：**在满分俱乐部内部，接口表征决定的是成本与速度，而非成功率**。文章提醒的消融缺口确实存在——"表征 vs 判断模型谁更重要"尚无隔离实验。
