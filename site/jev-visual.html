Jev 工程:为 Coding Agent
重新设计上下文

《Jev Engineering for Coding Agents》(基于 TypeSafe 创始人 Diogo Almeida 的设计笔记)主张:agent 的杠杆不在循环本身,而在循环每一轮喂给模型什么。

思想实验:「如果 LLM 没有 KV cache,你会怎么设计 coding agent?」

一、核心思想

为什么"拿掉 KV cache"这一个假设,能推翻今天 agent 的整个形态

今天的 agent:append-only 转写

复用缓存前缀很便宜;改前面任何内容都会让后面全部重算。这一个经济学事实,让 agent 变成"只追加的对话转写"——上下文靠累积,不靠设计。

没有 cache 的世界:按需组装

上下文从"不断累积"变成"主动组装(assembled, not accumulated)"。每个 chunk 可寻址、有类型,每轮重新决定谁出场。

Jev 不是写代码的模型

它是模型旁边的决策层:输入当前状态(目标、上下文、规则、可用动作、历史动作)+ 预定义问题,输出带概率的类型化答案:choice / score / noul。确定性代码负责验证、阈值、分支——不解析自然语言。

杠杆在哪

这类小决策每个会话要问上千次:下一轮看哪些 chunk?子任务要不要离开 frontier 模型?哪个工具匹配意图?这条命令能不能跑?——笔记认为全部杠杆都在这里。

四、六大继承病(Table II)

现有 agent 不加审视就继承的设计——全部可以由"显式状态 + Jev"一个动作治愈

路由失败

把执行交给便宜模型,再交回大模型时,整个上下文被重处理。

按"上下文重建"计价;给便宜模型小而专的上下文

工具挤占上下文

schema 必须常驻 system message,不管本轮是否相关。

摘要在前,schema 按需载入(见"工具分层")

压缩是盲目的

compaction 假设所有未来轮次共享同一状态,在知道问题之前压缩,必然丢掉后面需要的东西。

query-aware 压缩 / 可见度阶梯

子代理很少触发

决定"传什么上下文进去、如何合并回来"太贵太易错,模型干脆不开。

自动组装小上下文;结果作为打分 chunk 合并

重启即丢失

转写漂移后重启,好状态和坏状态一起扔掉。

可寻址状态:干净重启,只重载仍相关的 chunk

"电池"之争

每个内置能力都永久占用上下文,易用与强大被迫二选一。

内置能力"用到才花钱",争论自动消失

八、工具三层披露(重绘 Fig. 5)

模型看见一张"便宜的地图",只为它选中的少数工具付费,用完即从上下文清除

TIER 1 · 摘要

每个能力一行 · 相关时载入 · 数百个工具

低成本常驻

TIER 2 · 按需 Schema

只为选中的少数工具载入完整参数定义

↓ 花费上升

TIER 3 · 文档

仅供一次性查询时手动阅读

最贵

若内置能力"用到才花钱",电池之争自动消失:可以 ship 数百工具、数千文档页。模型用自然语言描述意图,harness 用一串 typed Jev 调用选工具并构造参数——错参数类型变成 validation error,而非静默失败。

九、条件式指令(重绘 Fig. 6)

(每个子目录一个 footguns 文件)

在写散文 ?

→ 载入文风样本 + 禁例清单

与 Skill 的关键区别

Skill 是"现在就做这个";条件式指令是"只要条件成立就持续记住"。后者需要 skill 缺少的属性:对 compaction 免疫——条件成立即重载(或被 pin 住不被摘要掉)。结构化 skills 可进一步携带行为变化(比 hook 更强:hook 一旦加上就永久驻留,结构化 skill 随条件挂载/卸载)。相关方向:递归语言模型(RLM, A. Zhang 2025)——把状态放进命名变量,而非"窗口里碰巧剩下的文本"。

十一、后台处理:共享一次检索(重绘 Fig. 7)

昂贵的"找出什么相关"只做一次,所有只读后台任务共享——鉴于检索占 token 最大头,这是单项最大的节省

主代理(写)

正常写代码、改文件;与共享检索层交互。

共享检索层

一次找出相关文件、符号、diff;read-only,永不争锁。

十三、我的批判性评价

解读者的立场,而非原文内容

👍 最强的点

对 KV cache 经济学如何塑造 agent 架构的刻画非常锋利:六大症状是统一框架下的推论,不是六条零散吐槽。"按 token 计价的定价让直觉正确的路由变贵"——每个做 multi-model 系统的人都该亲手重算一遍。

🛠️ 不动架构也能借鉴

query-aware 压缩 / 可见度阶梯;按条件加载 AGENTS.md 片段 + compaction 免疫;安全敏感度作为路由轴;后台任务共享检索;派生前目标去重。

⚠️ 未回答的关键账

"没有 KV cache"是反事实——prompt caching 真实存在且便宜。"每轮对每个 chunk 打分"的方案自身要花多少 token / 多少延迟?Jev 决策层自己的成本从未被记账,这是全文最大的空白。

🔍 可信度注意

数字均为示例;"Jev / TypeSafe / Diogo Almeida" 疑似匿名化占位名;fastcontext 的 56.2% / 46.5% 未核实;文档自称"独立编译的学习综述",是思路索引,行动前应回到原始设计笔记。

一句话:把上下文窗口当作"有目的地组装"的东西,而不是"意外累积"的东西。状态显式化、类型化,每个高频决策点由 Jev 回答带概率的类型化答案——这不需要更好的模型,只需要停止让上下文"堆积如山"。
